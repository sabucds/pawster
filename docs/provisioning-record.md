## The domain, and why nothing was bought

The map's old standing preference allowed one expense — *"a domain name is the
only accepted cost"* — and that allowance has been **withdrawn**. `$0` is now
absolute.

That does not mean no domain. [ADR 0014](adr/0014-the-domain-is-free-and-lives-outside-cloudflare.md)
separates two requirements the earlier plan had fused:

- **Images never needed a domain.** Workers Cache is zone-independent and caches
  on `workers.dev`, so the chain [ADR 0011](adr/0011-r2-custom-domain-requires-a-full-zone.md)
  built — cached images → R2 custom domain → Cloudflare zone → a bought domain —
  has nothing hanging off it any more. There will be **no R2 custom domain**,
  and ADR 0011 is superseded.
- **Email needs DNS, but not Cloudflare's.** A free subdomain of a Public
  Suffix List suffix satisfies Resend, which documents no restriction on which
  domains may be verified.

So four stages of the original wizard are not "deferred", they are **cancelled**:
the domain purchase, the Cloudflare zone, the R2 custom domain, and the Images
transformations observation (which needed a zone). Their replacement is
`scripts/provision-domain.sh`, seven stages, ten minutes, no cost.

Until that script is run, Resend reaches only this account's own address, so
shelter sign-in codes (ADR 0013), admin verification links (ADR 0002) and the
subscriber digest (ADR 0009) work for the operator alone.

**The one open observation**, which matters more than anything else here:
Google Postmaster Tools reports on *"primary domains only, not to subdomains"*
and never defines "primary domain". Whether Google scores mail as
`pawster.dpdns.org` or as the whole of `dpdns.org` cannot be determined from any
public source, and it is the single unknown that decides whether the free
subdomain was a good idea. Stage 6 of `provision-domain.sh` makes the
observation; make it before the first real digest, not after.

## Still unsettled

ADR 0012 says the originals lifecycle rule "also collects abandoned upload
sessions, so neither needs code" in ADR 0010's daily purge. It plainly collects
an abandoned session's **originals**, and R2's default multipart-abort rule
collects incomplete uploads. But ADR 0012 also stages *derivatives* before the
animal row is committed, and those are written to `pawster-media`, which
neither rule touches — so an abandoned session appears to strand its
derivatives there permanently. That is either a second lifecycle rule on a
staging prefix or a line of purge code, and it is a decision rather than a
mechanical gap. Worth settling before the upload path is built.
